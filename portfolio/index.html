コードでの関係性表現 (委譲とfriendクラス)

ポインタ同士で無駄な密結合を生まないよう、Playerオブジェクトへの「friend class」登録と「役割の明確な委譲」を行っています。

// player.h (スリム化された定義) class Player : public GameObject { friend class PlayerMovement; friend class PlayerCombat; friend class PlayerVisual; private: PlayerMovement* m_Movement; // 移動・物理担当 PlayerCombat* m_Combat; // 戦闘・アクション担当 PlayerVisual* m_Visual; // 描画・エフェクト担当 public: void Update() override { if (m_Movement) m_Movement->Update(); if (m_Combat) m_Combat->Update(); if (m_Visual) m_Visual->Update(); } };

ゲームループにおける $O(N)$ から $O(1)$ への最適化

エネミーや弾が「現在のプレイヤーの位置」を参照する際、以前は全登録オブジェクト（数百件）から毎フレームプレイヤーを探し出す `GetGameObject()` が実行されていました。 これは計算量が $O(N)$ となり、オブジェクトの増加に合わせてCPU負荷が上昇します。

対策として、オブジェクトを集中管理する `Manager` クラスに「プレイヤーポインタのキャッシュ」機構を組み込み、生成時にキャッシュを更新。 プレイヤー検索時の計算量を 完全な $O(1)$ （定数時間） に引き上げ、ゲームループを高速化しました。

ポインタキャッシュと constexpr による型分岐

// manager.h 内のオブジェクト取得関数 template<typename TargetType> static TargetType* GetGameObject() { // C++17の if constexpr を使用し、Player型の場合は探索をせずキャッシュを即時返却 if constexpr (std::is_same_v<TargetType, Player>) { return reinterpret_cast<TargetType*>(m_CachedPlayer); } // それ以外のオブジェクトのみリストから全走査 (O(N)) ObjectType targetType = TargetType::GetStaticType(); for (GameObject* gameObject : m_GameObjects) { if (gameObject && gameObject->GetObjectType() == targetType) return static_cast<TargetType*>(gameObject); } return nullptr; }
